# Adversarial review: recovery export and forced-command policy (2026-10-30)

Scope: `src/recovery.rs`, `src/recovery/paged.rs`, `src/forced_command.rs`, `src/ssh.rs`,
`src/bin/{witness-export,witness-ssh-gate,witnessctl}.rs`, the docs `RECOVERY.md`,
`FORCED_COMMAND.md`, `SSH_TRANSPORT.md`, `PROCESS_CRASH_DRILLS.md`, and the verification parts of
`tl-collator-wire` they use (`verify.rs`, `witness.rs`, `parse_canonical_text`). Baseline: master
at `74db104`, 60 ordinary witness tests passing before any change. Local review only; nothing was
posted or disclosed. Line numbers refer to the files after this change.

Result: no High or Medium defect found. Three Low defects were confirmed and fixed (wire formats
unchanged); the rest are accepted or documented residuals. The Lean model in `lean/` covers the
dispatch, authorization and acceptance rules and found nothing further.

## Areas reviewed with no defect found

* Authorization of export (`export_history`): scope, domain, version, operator id and challenge
  checks run before any file is touched; key separation compares parsed points, not strings, so a
  compressed and uncompressed spelling of one key cannot slip through; operator, witness and
  collator keys must be pairwise distinct; the signature is over the canonical request without
  `sigOperator`; range arithmetic uses checked add/sub with `start >= 1`, `count in 1..=max_records`,
  `finish <= checkpointSeq <= max_entries`; the request checkpoint must equal the on-disk anchor and the
  full replay result, so a valid-but-unanchored suffix, torn tail or stale checkpoint refuses.
* Domain separation: request, manifest and `latest` receipt use distinct `domain` strings inside the
  signed canonical text and different keys (operator versus witness), so the latest capability
  cannot obtain a signature usable as a manifest.
* Bounded resources: per-record, per-response, per-scan, record-count and wall-clock caps are
  enforced before allocation grows; every read is `take`-bounded; non-regular files (FIFO, symlink,
  directory) refuse; the CLI watchdog covers blocked stdin and stdout.
* Locking: the exporter takes the same exclusive lock as CAS and never opens `DurableTape`, so it
  cannot repair or truncate evidence.
* Offline acceptance (`PagedRecovery`, `verify_full_recovery`): pages must start at the next
  sequence with matching `prevHash`, stay inside one pinned target checkpoint, carry a unique
  caller-supplied challenge, match byte count and digest, and replay with full signature
  verification. A single failure blocks the verifier permanently. `finish` requires pages > 0,
  replay equal to the target, a fresh receipt under the pinned witness key with a challenge distinct
  from every export challenge, matching sequence, head and order count, and age within 30 s.
  Genesis (target 0) cannot be "recovered". Signatures are low-S enforced by libsecp256k1
  verification, so no malleable second signature exists.
* Forced command: fixed grammar over space-split ASCII words, no shell evaluation; the role comes
  from the administrator's `authorized_keys` argument, so the latest/CAS identity can only ever
  reach `witnessctl`, and `witness-export` is parsed only under the recovery role as the exact
  one-word command (`witness-export extra`, `sh`, `sftp` refuse). The child environment is cleared,
  only `TL_WITNESS_*` values from the root-owned policy are set, signed input travels on stdin,
  the empty genesis hash is passed as a real empty argv element, stderr is suppressed, and any
  non-success, timeout or truncated run exits 1 with a fixed message; partial recovery output cannot
  verify because `bytes`, `digest` and the manifest signature would not match.
